## Hallazgos

### Crítico

Ninguno.

### Importante

**I1. `ReaderScreen` lee muchos estados en su raíz: cada cambio vuelve a ejecutar las ~500 líneas del composable.**
- `app/src/main/kotlin/io/github/diegobr4nd/lectorbilingue/ui/reader/ReaderScreen.kt:148-193` (lecturas `barsVisible`, `label`, `direction`, `readingSettings`, `notice`, `tip`), `:370` (`currentHref`) y `:522` (`positionText(label)`).
- Por qué importa: `ReaderScreen` es un único ámbito de recomposición (*restart scope*: el trozo de código que Compose vuelve a correr cuando cambia algo que leyó). Al cambiar el porcentaje de la etiqueta o al mostrar/ocultar las barras (cada gesto de lectura) se rehacen `CardLabels`, ~20 `stringResource`, `rememberCardTexts`, `noticeTexts`, `chapterButtons`, etc. Hoy es barato y poco frecuente, pero el costo crece con cada función nueva del Lector (Fase 4).
- Arreglo: bajar cada lectura al hijo que la usa. Por ejemplo, la barra inferior recibe la `StateFlow` (o una lambda) y calcula su visibilidad con `derivedStateOf`:
  ```kotlin
  @Composable
  private fun ReaderBottomArea(vm: ReaderViewModel, readingOrder: List<String>, currentHref: () -> String?, ...) {
      val label by vm.label.collectAsStateWithLifecycle()
      val bars by vm.barsVisible.collectAsStateWithLifecycle()
      ...
  }
  ```
  A mediano plazo, partir `ReaderScreen` en `ReaderEffects` (efectos y oyentes), `ReaderOverlays` (barras, banda, consejo) y `ReaderSheets`.

**I2. Tres escrituras de estado durante la composición.**
- `app/src/main/kotlin/io/github/diegobr4nd/lectorbilingue/ui/nav/AppNav.kt:48` — `if (backStack.isEmpty()) backStack.add(...)`.
- `app/src/main/kotlin/io/github/diegobr4nd/lectorbilingue/ui/library/LibraryScreen.kt:335` — `deletingId = null` dentro del cuerpo.
- `app/src/main/kotlin/io/github/diegobr4nd/lectorbilingue/ui/reader/ReaderScreen.kt:524` — `bottomBar.targetState = bottomBarShown`.
- Por qué importa: escribir estado mientras Compose dibuja obliga a otra pasada en el mismo cuadro y, si algo ya leyó ese estado antes en la misma pasada (escritura "hacia atrás"), puede repetirse en bucle. Hoy funcionan, pero son el patrón que más errores raros causa en Compose.
- Arreglo:
  - `AppNav`: resolver el caso vacío en el `restore` del `listSaver` (`.ifEmpty { listOf(StartRules.start(...)) }`) y quitar la línea 48.
  - `LibraryContent`: derivar sin escribir y limpiar en un efecto:
    ```kotlin
    val deleting = deletingId?.let { id -> state.books.firstOrNull { it.id == id }?.takeIf { state.openingId != id } }
    if (deletingId != null && deleting == null) LaunchedEffect(deletingId) { deletingId = null }
    deleting?.let { book -> ConfirmDialog(...) }
    ```
  - `ReaderScreen`: `SideEffect { bottomBar.targetState = bottomBarShown }` (o `LaunchedEffect(bottomBarShown)`).

### Menor

**M1. `Book` es inestable (lleva `java.io.File` y viene del módulo `books`, sin compilador de Compose).**
- `app/src/main/kotlin/.../ui/library/LibraryScreen.kt:572` (`BookRow(book: Book, ...)`), `:630` (`Cover(file: File?, ...)`).
- Por qué: con *strong skipping* un parámetro inestable se compara por identidad (`===`). Room emite objetos nuevos en cada cambio (abrir un libro, guardar progreso), así que todas las filas se recomponen aunque no cambien.
- Arreglo: archivo de configuración de estabilidad (`composeCompiler { stabilityConfigurationFiles.add(...) }`) con `java.io.File` e `io.github.diegobr4nd.lectorbilingue.books.Book`, o pasar a `BookRow` campos simples (`coverPath: String?`).

**M2. Biblioteca: lista con varios tipos de fila sin `contentType`.**
- `app/src/main/kotlin/.../ui/library/LibraryScreen.kt:285-326`.
- Por qué: carga, tarjeta, aviso, vacío, importando y libros comparten el mismo reciclaje; con `contentType` Compose reutiliza solo filas del mismo tipo.
- Arreglo: `items(state.books, key = { it.id }, contentType = { "book" }) { ... }` y `contentType` en los `item(...)` fijos.

**M3. Índice sin `key`.**
- `app/src/main/kotlin/.../ui/reader/TocSheet.kt:90` — `itemsIndexed(entries)`.
- Arreglo: `itemsIndexed(entries, key = { i, e -> "$i:${e.href}" })` (el href puede repetirse con fragmentos). Licencias (`LicensesScreen.kt:69-81`) ya usa claves; le falta solo `contentType` (encabezado / fila).

**M4. El Lector serializa el `Locator` a JSON en el hilo principal en cada posición.**
- `app/src/main/kotlin/.../ui/reader/ReaderScreen.kt:324` y `:912` (`toJSON().toString()`).
- Por qué: `currentLocator` emite seguido durante el desplazamiento, pero solo se guarda una posición por segundo (`debounce(1_000)` en el ViewModel).
- Arreglo: guardar el `Locator` (o sus campos) en `ReaderPosition` y serializar en `save()`, ya en el hilo de IO.

**M5. Respuestas de la página parseadas en el hilo principal.**

- Por qué: en Intercalado y Solo traducción cada pausa de lectura trae el texto de ~10 párrafos; el JSON se lee en Main (pocos ms, pero en el momento en que la persona está leyendo).
- Arreglo: `withContext(Dispatchers.Default) { ParagraphScripts.parseVisible(json) }` en `visible()` y `paragraphsAt()`.

## Lo que está bien

- **Flujos y ciclo de vida:** todos los `StateFlow` se leen con `collectAsStateWithLifecycle`; los eventos (`LibraryEvent`) llegan por `Channel` + `receiveAsFlow` y se consumen con `repeatOnLifecycle(STARTED)`, con `rememberUpdatedState` para la navegación (`LibraryScreen.kt:153-176`).
- **Disco fuera del hilo principal:** portadas reducidas con `inSampleSize` en `produceState` + `Dispatchers.IO` (`LibraryScreen.kt:632-665`); licencias en IO (`LicensesScreen.kt:48, 120`); nombre del archivo importado en el ViewModel.
- **Efectos bien hechos en el Lector:** un único receptor para la fila de tarjetas (Channel), `collectLatest` para descartar posiciones viejas, `DisposableEffect(navigator)` que quita el oyente, `LifecycleEventEffect` para guardar al pausar, `Mutex` para no solapar preferencias, `rememberUpdatedState` en textos y tema usados desde corrutinas largas.
- **Estado:** `rememberSaveable` para hojas y diálogos (sobreviven al giro), pila de navegación guardable con `listSaver`, `remember(publication)` para el índice y el orden de lectura.
- **Listas:** claves estables en Biblioteca (`book.id`) y Licencias (`it.id`), `animateItem` que respeta "quitar animaciones".
- **Composables sin estado:** `LibraryContent`, `LanguagesContent`, `WelcomeContent`, `LicensesContent`, `TocContent`, `DirectionContent`, `ReadingSettingsContent`, `ReaderTopBar`, `ChapterNoticeBand`, `TipCard`: se previsualizan y se prueban solos; parámetros `modifier` en su lugar.
- **Previews:** cada pantalla tiene claro, oscuro y letra al 200 %; `ui-tooling` solo en `debugImplementation`.
- **Accesibilidad:** encabezados, `Role.RadioButton` + `selectableGroup`, `stateDescription` además del color, acciones con nombre (`onClickLabel`, `customActions` para borrar), regiones vivas moderadas (progreso cada 10 %), objetivos de 48 dp y diseño que se reacomoda con letra grande.
- **Tema y fuentes:** una sola copia de las fuentes en assets, familias creadas de forma perezosa, esquemas de color estáticos (sin recrearse por recomposición).
- **Privacidad en la interfaz:** los anuncios de TalkBack con texto del libro solo van al servicio de accesibilidad; nada se registra.
